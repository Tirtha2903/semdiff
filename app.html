Ask a question. Gemma 4 thinks, then calls the engine's tools to test its ideas before answering.

Where Gemma 4 is used

  1. Thinking modeReasons about a change before it answers.
  2. Function callingThe agent runs the engine's tools to test its own hypotheses.
  3. VisionReads assembly from a Ghidra or IDA screenshot.
  4. Local and openRuns through Ollama. e2b and e4b fit a laptop.
  5. GroundedThe engine proves changes. Gemma 4 explains and investigates.

How it works

  1. 1. ParseReads each function from the assembly.
  2. 2. ExecuteRuns it on hundreds of edge-case and random inputs.
  3. 3. ObserveRecords calls, memory writes outside the stack, and the return value.
  4. 4. MatchPairs functions by how similar their behavior is, not by name.
  5. 5. ProveClassifies each change and shows an input that proves it.
  6. 6. ExplainGemma 4, running locally through Ollama, turns those facts into plain English. It never decides what changed.

Supported instructions: mov, lea, add, sub, imul, shl, shr, and, or, xor, cmp, test, jmp, jcc, cmovcc, call, ret. Arguments arrive in rdi, rsi, rdx.

Roadmap

Built: compiling real C with your gcc, 32 and 64-bit x86 registers and flags, inlined-call and memcpy handling, the exploit finder, and the benchmark. Not built yet: reading ELF files directly through Ghidra, AArch64, vector (SSE/AVX) instructions, floating point, formal proofs with the Z3 solver, and learned embeddings. Overlapping memcpy and extreme loop bounds are treated as inconclusive, never as changes.
